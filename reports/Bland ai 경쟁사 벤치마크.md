# Bland는 스택을 소유하고, 우리 끊김은 브리지가 만든다

Bland AI는 아웃바운드 `POST /v1/calls` 하나에 약 45개 파라미터를 열어 둔 "키친싱크" 엔터프라이즈 음성 플랫폼이고, 그 위에 dev/staging/production 환경·평가 게이트·Testbed·Norm(AI 빌더)을 얹은 V2 Agents로 2026년 9월에 세대교체 중이다 ([V2 overview](https://docs.bland.ai/api-v2/overview.md); [Migrate to agents](https://docs.bland.ai/platform/migrate-to-agents)). 우리 제품(GPT-Live/Realtime + Twilio Media Streams 리셉셔니스트, 아웃바운드 콜백, 보이스메일 전사 대시보드)과의 차이는 "스택을 소유하느냐"보다 **통화 후 데이터 계약(녹음·서명된 웹훅·disposition), 테스트·평가·배포 게이트, 턴테이킹 하네스의 파라미터화** 세 축에 있고, 반대로 **실제 캘린더 예약(7개 제공자), 한국어, 보이스메일 전사, 사업자별 프롬프트 합성, 데모/CRM 파이프라인**은 Bland가 셀프서브로 제공하지 않는 우리 강점이다. Bland도 Twilio를 쓴다: BYO Twilio(`encrypted_key`)가 문서화되어 있고(documented), 자체 번호의 캐리어는 어디에도 적혀 있지 않으며(gap), 경쟁사 Telnyx는 "Twilio와 SIP 파트너를 경유한다"고 말한다(reported) ([Custom Twilio](https://docs.bland.ai/tutorials/custom-twilio); [Telnyx](https://telnyx.com/the-best-bland-alternative)). Bland가 안정적인 이유는 캐리어가 아니라 **자체 SIP/SRTP 엣지가 추론과 같은 AWS 리전에 붙어 있고, TTS를 48 kHz로 렌더링해 재생 버퍼를 거쳐 내보내며, 바지인을 단어 경계에서 "인정 vs 끼어들기"로 분류하고, 엔터프라이즈는 전용 파드에서 버전을 고정**하기 때문이다 — 그럼에도 2026-09-25에 BTTS V3 장애로 "delayed or missing agent audio"가 났고, 외부 관측 지연은 700–900 ms다 ([status.bland.ai](https://status.bland.ai/); [Retell benchmark](https://www.retellai.com/blog/retell-vs-bland-vs-vapi-vs-elevenlabs)). 우리 끊김의 원인은 코드가 이미 기록해 두었다: GPT-Live 출력이 **문장 중간에 최대 576 ms 멈추는 버스트**, 그것을 **0.5 s 프라임 + 0.6 s 리드 리저버가 다 덮지 못하는 것**, 그리고 우리 코드 안의 **호출자 전사 조각 하나에 리저버를 비우는 `_caller_started_talking`**, 인사말 창에서의 모델 오디오 폐기, 통화 중 `session.instructions.append` 넛지, 단일 uvicorn 워커 ([live_bridge.py:129-148](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L129-L148); [live_bridge.py:1009-1024](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L1009-L1024)). 최우선 수정은 (P1) 리저버 드롭을 실제 바지인 신호에만 게이트, (P1) 적응형 리드 버퍼 + Twilio `mark` 기반 재생 추적, (P1) Realtime 엔진에 페이싱과 `conversation.item.truncate` 추가이고, 구조적 대안으로 OpenAI SIP 커넥터(브리지 제거, raw audio 상실)를 번호 하나에서 A/B할 가치가 있다.

> 표기 규칙: 노트의 신뢰도 라벨을 그대로 유지한다 — **documented**(Bland/벤더 공식 문서·상태 페이지·코드), **Bland marketing claim**(1차이나 미감사), **reported**(제3자·경쟁사 블로그·이슈 스레드), **inferred**(노트 작성자의 추론). 우리 코드 인용은 `Main-Hans` 브랜치 HEAD `9ea7ab7`(2026-09-29) 기준 file:line이며, 링크는 이 문서(`reports/`)에서 상대 경로로 열린다.

## Bland는 통화 하나에 45개 파라미터를 열어 두고, V2 Agents로 배포 규율을 판다

Bland의 문서는 V2 "Agents"(빌더 `v2.app.bland.ai`, API `/v2/agents`)를 중심으로 재편됐지만, 실제 통화 런타임은 여전히 V1 원시 객체 — Send Call, Conversational Pathways, Personas, Inbound Numbers, Knowledge, Tools — 위에서 돌고 V2 문서 스스로 이들이 "unchanged"라고 못박는다 ([V2 overview](https://docs.bland.ai/api-v2/overview.md)). 마이그레이션은 2026년 9월 발표, **2026-11-15 이후 트래픽이 남은 pathway는 자동 이전·나머지는 보관**, 2026-09-18 이후 생성 계정은 새 시스템만 본다(documented) ([Migrate to agents](https://docs.bland.ai/platform/migrate-to-agents)). 따라서 벤치마크 대상은 V2 Agents(빌더 + 환경 + Conversations + Testbed + Evaluations)이되, 통화 파라미터 어휘는 V1 Send Call이 여전히 정본이다.

`POST /v1/calls`는 평평한 JSON 하나로 리셉셔니스트가 필요로 하는 거의 모든 토글을 담는다: 실행 대상(`task`/`pathway_id`/`persona_id`, `first_sentence`), `voice`(기본 `"Karen"`), 50개 `language` 코드(`babel-*` 즉석 언어 전환, `fluent` 자동 감지, `ko`/`ko-KR` 포함), 턴테이킹(`wait_for_greeting`, `interruption_threshold` 기본 500, `interruptibility` 0–3 기본 2, `block_interruptions`), 전사 보정(`keywords` 최대 20개 `"Reece:3"` 형식, `pronunciation_guide`), 오디오(`background_track` office/cafe/restaurant, `noise_cancellation` 기본 true, `record`), 음성메일(`voicemail {message, action: hangup|leave_message|leave_message_and_sms|ignore, sms, sensitive}`), `retry {wait, voicemail_action, voicemail_message}`, 전환(`transfer_phone_number`, `transfer_list {default, sales, support, billing}`), 데이터(`tools ["TL-…","KB-…"]`, `dynamic_data`, `request_data`), 후처리(`webhook` + `webhook_events`, `summary_prompt` ≤2000자, `dispositions`), 컴플라이언스(`guard_rails` `tcpa:ai_disclosure|self_introduction|recording_disclosure|opt_out|custom`) ([Send Call](https://docs.bland.ai/api-v1/post/calls.md)). Send Call에는 **`model` 파라미터가 없고**(documented), 인바운드 번호 설정 `POST /v1/inbound/{number}`에만 `model base|turbo`, `fallback_number`("Forwards calls during maintenance windows"), `memory_id`가 추가된다 ([Update Inbound Number](https://docs.bland.ai/api-v1/post/inbound-number-update.md)). 번호는 **$15/월, 셀프서브는 US/CA만** ([Purchase Phone Number](https://docs.bland.ai/api-v1/post/inbound-purchase.md)); 웜 트랜스퍼(프록시 번호로 사람에게 브리핑 후 3자 병합, 홀드 뮤직, DTMF `w54`, 홀드 타임아웃 30–3600 s)는 **엔터프라이즈 전용**이다 ([Warm Transfer](https://docs.bland.ai/tutorials/warm-transfer.md)). 2026-08-03 체인지로그는 호출자 말 속도를 학습해 최대 ~2.5 s까지 기다리는 "Adaptive resumption"과 노드별 interruptibility를 추가했다 ([Changelog 2026-08-03](https://docs.bland.ai/changelog/08_03_2026.md)).

빌더 층은 세 세대가 공존한다. Pathways는 11개 노드 타입(`Default, End Call, Transfer Call, Webhook, Knowledge Base, SMS, Custom Code, Press Button, Wait for Response, Transfer Pathway, Scheduling`)의 그래프이고 노드별 `modelOptions.interruptibility`·`temperature`, 추출 변수, 글로벌 노드, 버전(draft → production)을 가진다 ([Update Pathway](https://docs.bland.ai/api-v1/post/update_pathways.md)); "Flex Mode"는 엣지를 제안으로 격하시켜 에이전트가 스스로 다음 노드를 고르게 한다 ([Flex Mode](https://docs.bland.ai/tutorials/flex-mode.md)); 엔터프라이즈 Scheduling Node는 "Get Available Slots Webhook"과 루프 조건("the agent must explicitly repeat the date and time back to the user, and the user must agree")으로 `chosen_datetime`을 뽑는다 ([Scheduling Node](https://docs.bland.ai/enterprise-features/scheduling-node.md)). V2 Agent는 노드용 "Prompt"와 전역 "System Prompt" 두 필드, 프롬프트 안 `@check-calendar` 식 툴·지식 태깅("Building a tool without tagging it fails silently"), dev/staging/production 환경, Publish(patch/minor/major) → Promote, 평가를 프로모션 체크로 거는 구조다 ([Agent builder](https://docs.bland.ai/agents/agent-builder.md)). 지식베이스는 PDF/TXT/CSV/JSON/DOCX(각 ≤10 MB), 붙여넣기 ≤100만 자, 사이트맵 기반 "Discover from a site" + 일일 동기화, Notion/Google Docs 동기화, 검색 테스트와 버전 편집을 제공한다 ([Knowledge](https://docs.bland.ai/agents/knowledge.md)). v2 Tools는 OpenAI 스타일 `input_schema`에 **HTTP 호출 중 말할 `speech`, `timeout` 1–60 s, `max_retries` 0–4, `cache`, JSON-path `response_data`**를 붙이며 통합 enum은 `bland-sms, custom-code, slack, salesforce, rest_api, hubspot, calendly, cal-com-v2, notion`이다 ([Create Tool v2](https://docs.bland.ai/api-v2/post/tools.md)) — Google Calendar는 1차 통합이 아니고 Cal.com/Calendly 또는 웹훅 Scheduling Node로 우회한다(inferred).

통화 후·운영 층은 Bland가 가장 두터운 곳이다. 메모리는 연락처 단위(사실·롤링 요약·미결 항목·엔티티, 전화번호/이메일로 자동 연결)로 "Memory belongs to the contact, not to any one conversation"이다 ([Memory](https://docs.bland.ai/tutorials/memories.md); [Conversations](https://docs.bland.ai/agents/conversations.md)). 통화 후 웹훅은 `summary, disposition_tag, variables, recording_url, recording_expiration, answered_by, call_ended_by, transferred_to, pre/post_transfer_duration, price, corrected_transcript` 등을 싣고 **HMAC-SHA256 `X-Webhook-Signature`**로 서명된다 ([Post Call Webhooks](https://docs.bland.ai/tutorials/post-call-webhooks.md); [Webhook Signing](https://docs.bland.ai/tutorials/webhook-signing.md)). `POST /v1/calls/{id}/analyze`는 `goal` + `[질문, 기대 타입]` 배열로 구조화 Q&A를 뽑는다 ([Analyze Call](https://docs.bland.ai/api-v1/post/calls-id-analyze.md)). Alerts는 통화 길이/API 오류(전 플랜)와 지연·전사 점수·침묵 횟수·감정(엔터프라이즈)에 INFO/WARNING/CRITICAL 임계값을 걸어 이메일·**아웃바운드 전화**·Slack/PagerDuty로 보내고 ([Alerts](https://docs.bland.ai/tutorials/alerts.md)), Triggers는 14개 이벤트(voicemail detected, inbound call received, knowledge gap detected 등) → 조건 → Call/SMS/Webhook/Slack/Custom code 액션에 "business hours" 타이밍을 붙인다 ([Triggers](https://docs.bland.ai/agents/triggers.md)). 배치는 `phone_number` 열만 필수인 CSV(125 MB, 행 제한 없음)로 열 이름이 `{{variable}}`가 되고 DNC·중복은 다이얼 시점에 걸러진다 ([Dispatch](https://docs.bland.ai/agents/dispatch.md); [Create Batch](https://docs.bland.ai/api-v2/post/batches.md)). SMS/RCS/iMessage/WhatsApp는 **엔터프라이즈 전용, $0.02/건, A2P 등록 필수** ([Messaging: SMS](https://docs.bland.ai/tutorials/messaging/sms.md)); 웹 위젯과 `@blandsdk/client` SDK가 브라우저 채널을 맡는다 ([Web Agent SDK](https://docs.bland.ai/sdks/web-agent-sdk.md)). 음성은 자체 BTTS_V3 엔진, 프리셋 3종 + 크리에이터 보이스, ~10초 샘플 1개로 17+개 언어 즉석 클로닝, `consistency`/`expressiveness` 조절이다 ([Choosing a Voice](https://docs.bland.ai/tts/voices.md)). 가격은 **Start 무료 $0.14/분(100통/일, 동시 10), Build $299/월 $0.12/분, Scale $499/월 $0.11/분**, LLM+STT+TTS 번들·토큰 과금 없음·텔레포니 별도이고 ([Pricing](https://www.bland.ai/pricing)), 소상공인 정면 타깃은 **Agent Phone Plan $29.99/월(첫 달 $14.99): 미국 로컬 번호 1개, US/CA 무제한 통화·SMS, 동시 통화 1**이다 ([Agent Phone Plan](https://docs.bland.ai/platform/agent-phone-plan.md)). 엔터프라이즈는 SAML/OIDC SSO, 조직 권한(`owner|admin|operator|viewer`), 감사 로그, SOC 2 Type II·HIPAA BAA·GDPR DPA·PCI DSS v4.0, VPC/온프렘/에어갭 배포를 더한다 ([Trust & Security](https://www.bland.ai/trust-security); [SSO](https://docs.bland.ai/enterprise-features/SSO.md)).

표를 관통하는 해석은 세 가지다. 첫째, **Bland의 통화 설정 어휘는 우리 UI의 "사업자 언어"보다 낮은 층(하네스)에 있다** — `keywords`, `pronunciation_guide`, `interruptibility`, `background_track`, `summary_prompt`는 우리에게 아직 노출된 적이 없는 품질 손잡이다. 둘째, **우리 대시보드는 전화가 실제로 하는 것보다 앞서 있다**(웜/워터폴/홀드 뮤직/SMS 링크는 UI만) — 팀 감사도 이를 인정한다 ([HISTORY.md:70-72](../HISTORY.md#L70-L72)). 셋째, Bland는 **"통화가 끝난 뒤"에 가장 많은 것을 판다**(서명 웹훅, disposition, 메모리, 알림, 트리거)인데 우리는 그 층이 사실상 비어 있다. 반면 Bland가 셀프서브로 못 주는 것 — 진짜 캘린더 예약, 한국어 실전, 보이스메일함 전사, 영업 데모 파이프라인 — 은 우리가 이미 갖고 있으므로 "따라잡기"보다 "빈 층 채우기 + 하네스 노출"이 맞는 프레임이다.

## Bland UX의 핵심 원칙은 "모든 실제 통화가 테스트 픽스처"다

온보딩은 대시보드 홈의 4단계 체크리스트다: "Blank agent" 생성 → **"Talk in browser"(마이크) 또는 "Call me"(내 전화로 걸어 줌)** → "Promote to production" → 그 통화의 전사·턴별 결정·녹음 보기. "Nothing you do here needs a phone number, a plan or a purchase"이고, "An agent that has not been promoted to production cannot take a call from anyone else"가 3단계에서 강제 학습된다 ([Build your first agent](https://docs.bland.ai/build-your-first-agent)). 워크스페이스에 예시 에이전트 "Norma"가 딸려 오지만 "an agent to look at, not to build on"이며 업종 템플릿은 없다(documented); 번호는 온보딩 뒤 Dispatch에서 무료 1개/구매/Twilio 연결로 붙인다 ([Dispatch](https://docs.bland.ai/agents/dispatch)). 경쟁사 Coval은 "Configure a basic agent in 20-30 minutes"라 하고(reported), Lindy(2025-11)는 "Setup takes effort if you're not technical"이라 했다(reported, Norm 이전) ([Coval](https://www.coval.ai/blog/bland-ai-review-2026-features-pricing-and-when-to-use-it/); [Lindy](https://www.lindy.ai/blog/bland-ai-review)).

빌더는 세 영역(사이드바 / Prompt·Settings 탭 / Graph·Testing 우측 컬럼)이고 프롬프트 우선·그래프는 옵션이다. 툴과 지식은 프롬프트 안에서 `@name`으로 붙이며 "Variables to extract"에는 "Each one costs a little response time"이라는 경고가 박혀 있다 ([Agent builder](https://docs.bland.ai/agents/agent-builder)). 프롬프트 가이드는 음성 특화다: "Talk like a person on a phone, not like written copy", 간투사와 말 고침 허용, `[say warmly]`·`[laughs]` 같은 퍼포먼스 태그(한 줄 2개 이하), "Read every line aloud. If it sounds like an essay, rewrite it." ([Making calls sound human](https://docs.bland.ai/platform/sounding-human)). 2026년 4월에는 실시간 다중 편집("Multiplayer Pathways", 라이브 커서와 변경 diff 리뷰)과 GitHub 연동 버전 리뷰가 들어갔다 ([Changelog](https://www.bland.ai/changelog)).

테스트 스택이 Bland UX의 정수다. **Testbed는 "실제 대화의 한 순간"을 골라 그 턴만 N번 재실행해 답변을 동일 그룹으로 묶어 `count/total` 배지로 보여 주는 "a stability reading rather than a pass or a fail"**이고, 전사 턴의 호버 메뉴(Dialogue/Route/Loop condition/Variable extraction)나 이벤트 행에서 바로 열린다 ([Testbed](https://docs.bland.ai/agents/testbed)). Evaluations는 judge(Transcript/Audio 모드) × test case(직접 작성 또는 "Generate based on production calls"로 실제 통화 50건에서 생성) × run이며, 최대 5개 judge/test case를 staging의 필수 체크로 걸어 **publish와 promote 두 홉을 모두 게이트**한다 — 다만 수동 실행 결과가 "stored in your browser, not on Bland"인 거친 면이 문서에 그대로 적혀 있다 ([Evaluations](https://docs.bland.ai/agents/evaluations); [Environments](https://docs.bland.ai/agents/environments)). 레거시 Scenarios는 9개 호출자 페르소나 템플릿(Voicemail, Angry Caller, Confused Caller…), 10개 assertion 타입(`LLM_JUDGE, BLAND_TONE, VARIABLE_EXTRACTED, NODE_REACHED, WEBHOOK_TRIGGERED, REGEX_MATCH…`), 플래키 감지, "Production Gate", 그리고 실패를 분석해 수정안을 포크에 적용하고 통과할 때까지 반복하는 "Tornado" 모드를 갖는다 ([Scenarios](https://docs.bland.ai/tutorials/scenarios)).

통화 상세(Conversations)는 라이브 목록 위에 뜨는 우측 슬라이드오버 패널이다: Transcript/Detail/Logs 타임라인, 하단 고정 녹음 플레이어(결정=초록, 추출=호박색 마커가 찍힌 파형, 전사와 동기 스크롤), 턴별 호버 액션 **"Raw LLM context / Edit node / Open turn in Testbed / Report transcription issue"**, 우측 접이식 컬럼(Metadata·비용·요약, Variables, Citations, Notes & Review 상태, Webhook & Tools 재전송, Guardrails, Memory, Metrics), 모든 음성 행의 Flag → 심각도·담당자 있는 Issue 생성 ([Conversations](https://docs.bland.ai/agents/conversations); [Call Logs](https://docs.bland.ai/tutorials/call-logs)). 확장 로그는 턴마다 선택 노드·프롬프트·루프 조건 확률·**선택된 경로와 대안 경로**·웹훅 상태 코드를 펼친다(documented). 반면 검색은 로드된 행의 연락처/경로명/ID만 뒤지고 전사는 못 찾으며, 열 헤더 정렬이 안 되고, 내보내기는 서버에서 30–180일 범위로 이메일 전달된다(documented rough edges).

분석은 얇다. 셀프서브 문서에 기본 KPI 대시보드가 없고, 2026-04-30 "Analytics Dashboards Overhaul"은 **엔터프라이즈 전용**으로 KPI 타일/라인/바/파이/테이블/산점도 패널을 직접 조립하거나 "Daily call volume per pathway for the last 30 days"처럼 말로 생성한다 ([Analytics overhaul](https://bland.ai/changelog/2026-04-30-analytics-dashboards-overhaul)); Norm에게 "How many calls failed yesterday?"를 물어 차트를 받는 게 대안이다 ([Norm](https://docs.bland.ai/tutorials/norm)). 라이브는 "Active" 탭(진행 중 통화·경과 시간·클릭 시 라이브 전사, 조직 설정에 따라 listen-in)이고 음성에는 위스퍼/바지인 개입이 문서화되어 있지 않다 ([Conversations](https://docs.bland.ai/agents/conversations)). 지식 UX는 "Discover from a site"가 사이트맵을 읽어 전부 선택된 채 돌아오고, 7일 이상 동기화 안 되면 "Stale" 배지, "Source testing"이 생성 쿼리·gap 판정·랭킹된 청크를 보여 준다 ([Knowledge](https://docs.bland.ai/agents/knowledge)). Triggers 빌더는 좌측 캔버스("The canvas is a picture, not an editor") + 우측 스텝 편집기, "Conditions only"/"Full test"(실과금) 테스트, Runs 탭 — 그리고 "If a required field is missing, Save does nothing: no message, no error"라는 결함이 문서에 있다 ([Triggers](https://docs.bland.ai/agents/triggers)).

개발자 경험은 "코딩 에이전트 네이티브"로 요약된다: `docs.bland.ai/llms.txt`와 모든 페이지의 `.md` 미러, 원격 MCP 서버(`https://api.bland.ai/v1/mcp`, 조직당 120 req/min, 파괴적 작업은 확인 필요), `bland-cli`(디바이스 코드 로그인, YAML pathway push/pull/validate, `bland eval`, `bland listen --forward-to http://localhost:3000/webhook`로 ngrok 없이 웹훅 포워딩), Claude Code/Cursor/Codex용 `norm@bland` 플러그인 ([CLI](https://docs.bland.ai/sdks/cli); [MCP overview](https://docs.bland.ai/integrations/mcp/overview)). API 레퍼런스에는 카테고리별 "Error Codes Reference" 아코디언이 있으나 try-it 플레이그라운드·다국어 스니펫·OpenAPI·샌드박스 키는 없다(documented gap). Norm(2026-03-25 출시)은 대시보드 채팅·에디터 패널·iMessage·Claude Code 네 곳에서 "describe what you want in plain English"로 에이전트를 만들고 고치되, **Draft(포크) → Commit(버전) → Link(라이브 연결)** 안전 모델과 노드/엣지 단위 diff를 강제한다 ([Norm](https://docs.bland.ai/tutorials/norm); [Norm launch](https://www.bland.ai/blog/norm-build-voice-agents-from-prompt)).

## Bland도 Twilio를 쓴다 — 차이는 캐리어가 아니라 미디어 종단점과 페이싱이다

Bland의 텔레포니 진입로는 셋이다. (1) Bland 제공 번호 $15/월(US/CA), 캐리어 미기재(documented gap) ([Purchase Phone Number](https://docs.bland.ai/api-v1/post/inbound-purchase)); (2) **BYOT(Bring Your Own Twilio)**: Twilio Account SID + Auth Token으로 한 번만 보이는 `encrypted_key`를 만들고, 가져온 번호로 인·아웃바운드를 "through Bland's infrastructure"로 돌리며, 국제 통화 권한은 Twilio Geo Permissions를 상속한다(documented) ([Custom Twilio](https://docs.bland.ai/tutorials/custom-twilio)); Twilio Studio Flow 연동은 `bland_widget`이라는 **twiml-redirect 위젯**으로 Bland의 incoming URL을 가리킨다(documented) ([Bland + Twilio](https://www.bland.ai/integrations/twilio)); (3) SIP 트렁킹: `us2|ca2|asia2|eu2.sip.bland.ai`, **TLS 1.2+ 5061 전용, SRTP `AES_CM_128_HMAC_SHA1_80` 전용, UDP 16384–32768, 코덱 PCMU/PCMA/Opus/G.722(+G.729)**, REFER 전환, 포팅 API(7–14 영업일) — 2026-03-23부터 전 조직 개방 ([SIP Integration](https://docs.bland.ai/enterprise-features/SIP-integration); [Agents → SIP](https://docs.bland.ai/agents/sip); [Changelog 2026-03-23](https://docs.bland.ai/changelog/03_23_2026.md)). "Bland owns its telephony and AI stack. Not a wrapper around third-party APIs"는 Bland marketing claim이고 ([ai-information](https://www.bland.ai/ai-information)), Telnyx는 "routes calls through Twilio, so every call inherits someone else's network"라고 반박한다(reported, 근거 미제시) ([Telnyx](https://telnyx.com/the-best-bland-alternative)); Twilio 공동창업자 Jeff Lawson이 Series A·C 엔젤이다(documented) ([Scale VP](https://www.scalevp.com/press/bland-ai-emerges-from-stealth-with--16m-series-a-led-by-scale-venture-partners)). 노트의 추론(inferred, 중간 신뢰)은 **Bland 자체 번호는 Twilio급 CPaaS로 발급·착신되고, "own telephony"는 SIP 엣지와 미디어 처리를 뜻한다**는 것이다. 동종 업체(Vapi, Retell, ElevenLabs, Synthflow) 모두 리전 SIP 엣지 + Twilio/Telnyx/Vonage 임포트 구조이며, **누구도 캐리어 상호접속을 소유했다고 문서화하지 않는다**(inferred) ([Vapi SIP](https://docs.vapi.ai/advanced/sip); [Retell custom telephony](https://docs.retellai.com/deploy/custom-telephony); [ElevenLabs SIP](https://elevenlabs.io/docs/agents-platform/phone-numbers/sip-trunking)).

미디어 경로는 SIP 고객에 한해 문서화되어 있다: 캐리어/PBX → Bland SBC(SRTP) → 같은 AWS 리전의 STT/LLM/TTS → 되돌아감, 즉 **RTP 종단 한 번, 오디오의 텍스트/JSON 재인코딩 없음**(inferred). Bland의 컴퓨트는 AWS us-west-2(Oregon)·ca-central-1·ap-southeast-2·eu-west-1 + Cloudflare이고 SIP 시그널링/미디어 IP는 별도다(documented) ([Static IPs](https://docs.bland.ai/platform/static-ips); [status.bland.ai](https://status.bland.ai/)). 실시간 TTS는 **48 kHz PCM s16le를 네이티브 렌더링 속도로 권장하고 8 kHz μ-law 출력 옵션**을 두어, 합성 품질이 마지막 홉까지 코덱에 묶이지 않는다(documented) ([Realtime TTS concepts](https://docs.bland.ai/tts/realtime-concepts)). 대조적으로 Twilio Media Streams는 "must be encoded `audio/x-mulaw` with a sample rate of `8000`", 모노, base64이고 `mark`/`clear`는 양방향 스트림에서만 동작한다(documented) ([Twilio WebSocket messages](https://www.twilio.com/docs/voice/media-streams/websocket-messages)). Bland 자체 번호/BYOT 통화가 Media Streams를 타는지 `<Dial><Sip>`로 엣지에 붙는지는 미문서(gap).

추론 스택은 "전 층 자체 모델" 주장이 일관되지만 검증 수준이 층마다 다르다. STT "Babel"은 CEO 명의 기술 블로그에 **NVIDIA A100, 커스텀 CUDA 커널, 동적 마이크로배칭, sub-100 ms TTFT**, 동적 SNR 추정 기반 노이즈 억제가 적혀 있다(documented, 1차) ([Bland Babel](https://www.bland.ai/blog/bland-babel-ai-transcription-optimization)). TTS "BTTS"는 SNAC 오디오 토큰을 직접 예측하는 decoder-only transformer, 자체 2채널 대화 데이터로 학습(documented) ([New TTS](https://www.bland.ai/blog/new-tts-announcement)); BTTS V3는 2026-08-05 릴리스, "trained on 100M+ real phone conversations"(aggregator가 Bland 주장을 반복, reported) ([benchlm.ai](https://www.benchlm.ai/models/bland-speech-v3)). LLM은 "Proprietary models (transcription, LLM, TTS)"라는 마케팅 문장 외 아키텍처·크기·서빙 정보가 전무하다(Bland marketing claim) ([Bland vs Retell](https://www.bland.ai/compare/bland-vs-retell)). 삭제된 Baseten 케이스 스터디("Initially, response delays were as high as three seconds… under 400 milliseconds")는 2024년 추론이 제3자 플랫폼에 있었음을 보여 준다(reported; 원본 404) ([casestudies.com](https://www.casestudies.com/company/baseten)). 지연은 Bland가 "Under 400ms"(marketing) ([Bland vs Retell](https://www.bland.ai/compare/bland-vs-retell)), 경쟁사 관측은 **700–900 ms**(Cekura 리뷰어 관측, reported) 및 "700ms to 1,500ms… up to 2,500ms in stress tests"(reported, 방법론 미공개)이며 독립 반복 벤치마크는 없다 ([Retell benchmark](https://www.retellai.com/blog/retell-vs-bland-vs-vapi-vs-elevenlabs); [Retell Vapi-vs-Bland](https://www.retellai.com/blog/vapi-vs-bland)). 참고로 프로덕션 음성 AI 전반의 실측은 P50 1.4–1.7 s, P95 4.3–5.4 s이고 목표선은 <800 ms다(reported) ([Hamming.ai](https://hamming.ai/blog/voice-ai-latency-whats-fast-whats-slow-how-to-fix-it)). 노트의 결론(inferred): **Bland가 파는 것은 더 낮은 바닥이 아니라 분산과 통제(co-location, 전용 파드, 버전 고정)다.**

턴테이킹 하네스가 우리에게 가장 직접적인 교훈이다. Bland의 `interruptibility`(0 차단 ~ 4 항상 끼어들기, 기본 2 "Balanced")는 **"The agent doesn't cut off immediately—it finishes the current word while determining whether the caller is interrupting or acknowledging"**, 짧은 인정("uh-huh")은 그대로 말하고, 긴 인정은 멈췄다가 "resumes exactly where it stopped", **"The agent always stops at a word boundary. It never cuts off mid-word"**이며, `interruption_threshold`는 턴 종료 인내(기본 500, "lower = responds more quickly")로 바지인 민감도와 분리된 손잡이다(documented) ([Agent Speech](https://docs.bland.ai/tutorials/agent-speech); [Send Call](https://docs.bland.ai/api-v1/post/calls)). Resumption은 설정 없이 호출자 속도를 학습해 최대 ~2.5 s를 기다리고 15 s 안에 재적응한다(documented). TTS 프로토콜은 `context_id`로 "immediately preempts the active turn", 클라이언트는 "must discard unplayed audio locally after preemption", 그리고 Bland가 "accumulates the deltas, detects useful speech boundaries, and releases text to synthesis"한다 — 합성과 전송 사이에 재생 버퍼가 있다는 뜻이다(documented → inferred) ([Realtime TTS concepts](https://docs.bland.ai/tts/realtime-concepts)). `background_track`은 "plays continuously when the agent isn't speaking"이라 컴포트 노이즈 역할로 짧은 갭을 가린다(inferred). 인프라 측면에서 엔터프라이즈는 "real, provisioned Kubernetes pods exclusive to each organization", 선택 버전 고정("No surprise upgrades"), 통화를 끊지 않는 롤링 업데이트, 1/25/50/100% 캐너리다(documented) ([Infrastructure & Releases](https://docs.bland.ai/enterprise-features/infrastructure-and-releases)). 그러나 **2026-09-25 BTTS V3 장애는 두 창(8:10 PM–2:00 AM PT, 6:25–8:35 AM PT)에서 "delayed or missing agent audio"**를 냈고 서비스 재시작으로 해소됐다(documented) ([status.bland.ai](https://status.bland.ai/)) — 스택 소유가 끊김 면역을 주지는 않으며, "빠진/늦은 에이전트 오디오"의 원인이 네트워크가 아니라 합성 단계일 수 있다는 진단적 유비다(inferred).

## 우리 끊김의 원인은 코드가 이미 기록해 두었다: 버스트, 리저버 드롭, 넛지

먼저 어느 엔진이 실제 통화를 받는지가 중요하다. `openai-agent-app`은 `OPENAI_LIVE_MODEL`이 비면 Realtime(`bridge.py`, `gpt-realtime-2.1`), 설정되면 GPT-Live(`live_bridge.py`, `gpt-live-1` + `gpt-5.6-terra` delegate)로 분기한다 ([server.py:331-334](../openai-agent-app/src/openai_agent/telephony/server.py#L331-L334)). 2026-09-18 스터터 수정 15개 커밋, 사전 렌더 인사말, 넛지, 2026-09-29 "대시보드 프롬프트를 실제 통화에 적용"이 전부 `live_bridge.py`에만 있고 체인지로그가 그것을 고객에게 광고하므로 **프로덕션은 GPT-Live 엔진**이라 보는 것이 타당하다(inferred; VPS `.env`는 리포에 없음) ([HISTORY.md:22-26](../HISTORY.md#L22-L26); [changelog.ts:42-45](../tecace-voice-agent-dashboard/src/changelog.ts#L42-L45)). 브라우저 테스트 콜은 `transcribe-backend`가 GPT-Live에 WebRTC로 직결하므로 **전화에서만 재현되고 테스트 콜에서는 안 나는 끊김은 Twilio/μ-law/Python 브리지 쪽**이다(inferred) ([testCalls.ts:75-128](../transcribe-backend/src/routes/testCalls.ts#L75-L128); [openai.ts:143-168](../transcribe-backend/src/demo/openai.ts#L143-L168)).

GPT-Live 브리지의 설계 자체가 원인 1번을 문서화한다. 주석 그대로: **"GPT-Live does not send at a steady rate: it bursts, then stalls — measured at up to 576ms of nothing in the middle of a sentence, with this process idle throughout"**, "Measured on a real call: ten gaps, four seconds in total, with the lead never above 0.1s" ([live_bridge.py:129-148](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L129-L148)). 대응은 인프로세스 바이트 리저버 + 전용 송신 태스크: 턴 시작 시 **0.5 s를 모으거나 마지막 델타 후 0.15 s가 지나면** 송신 시작, Twilio에 **≤0.6 s**만 앞서 두고, 800바이트(100 ms) 청크로 보내며 `play_until`을 진행 ([live_bridge.py:149-170](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L149-L170); [live_bridge.py:1040-1093](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L1040-L1093)). 즉 이 설계는 **약 1.1 s까지의 상류 정지를 흡수하고, 그 이상은 "agent audio ran dry for %.0fms — the caller heard a gap"으로 기록**한다 ([live_bridge.py:909-933](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L909-L933)). 통화 종료 로그가 최대 재생 리드·언더런 횟수와 함께 "the stalls are upstream" vs "THIS PROCESS was blocked; that is ours to fix"를 판정하는데 ([live_bridge.py:1725-1744](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L1725-L1744)), **리포에는 끊긴 통화의 로그 발췌가 하나도 없다**(gap). 따라서 우선순위 0은 "끊긴 통화 3건의 종료 로그를 모아 upstream/process 비율을 읽는 것"이다.

원인 2번은 온전히 우리 코드다. `session.input_transcript.delta`(호출자 전사 조각, VAD 이벤트가 아님)가 올 때마다 `_caller_started_talking`이 실행되어 **리저버에 150 ms 이상 들어 있으면 `del state["out"][1200:]`로 나머지를 버린다** ([live_bridge.py:799-829](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L799-L829); [live_bridge.py:1009-1024](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L1009-L1024)). 그런데 GPT-Live는 "a fifteen-second answer can land in about a second and then sit in the reservoir being paced out"이므로 ([live_bridge.py:1575-1589](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L1575-L1589)), "mm-hm", 호출자 에코, 방 안 대화가 전사되는 순간 **에이전트 문장의 나머지가 통째로 사라지고 다음 델타부터 뒤쪽 지점에서 재개**된다 — "문장이 끊겼다가 뒤에서 이어진다"는 체감과 정확히 일치한다(inferred). 같은 함수의 주석은 "a caller saying 'mm-hm' should not chop off the sentence they are agreeing with"라며 Twilio `clear`를 피하지만, 리저버 드롭이 같은 결과를 만든다. 이것은 Bland가 "인정 vs 끼어들기"를 분류하고 단어 경계에서만 멈추는 것과 정반대 방향의 설계다.

나머지 후보는 순위대로다. **인사말 창**: `greeting_until`이 남아 있는 동안 모델 델타를 전부 `continue`로 버리고, 호출자가 인사말에 끼어들면 창을 +0.15 s로 자르고 Twilio를 `clear`한다 — 모델이 일찍 답하면 첫 단어가 사라진다 ([live_bridge.py:776-780](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L776-L780); [live_bridge.py:1025-1037](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L1025-L1037)). **통화 중 append 넛지**: `_NUDGE`, `_ASK_ANYTHING_ELSE`, `_GREET_AGAIN`, `_STILL_NEED_THE_MESSAGE`, 한국어 가이드, 작별/전환/음성메일 지시 등이 `session.instructions.append`로 들어가는데, 주석이 회귀를 기록한다: append가 호출자 발화 중에 떨어져 "Sure. We're at" 뒤에 "Anything else I can help with?"를 두 번 말했다 ([live_bridge.py:123-128](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L123-L128); [live_bridge.py:1136-1340](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L1136-L1340)) — 풀듀플렉스 모델에서 이것은 호출자에게 "문장이 멈춤"으로 들린다. **단일 워커**: `python:3.12-slim`, `uvicorn … --port 5050`(워커 없음), 리소스 제한 없음, 통화당 50프레임/초 `json.loads` + 10 ms 폴링 송신 루프 + 50 ms 시계 감시 + 0.5 s 넛지 루프, 인사말 캐시 미스 시 순수 Python DSP 스레드(GIL 점유) ([Dockerfile:15](../openai-agent-app/Dockerfile#L15); [docker-compose.yml:13-49](../openai-agent-app/docker-compose.yml#L13-L49); [live_bridge.py:1055-1057](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L1055-L1057); [greeting_audio.py:81-100](../openai-agent-app/src/openai_agent/realtime/greeting_audio.py#L81-L100)). **Twilio 버퍼 미정리**: GPT-Live 경로는 실제 끼어들기에도 Twilio 측 ≤0.6 s를 비우지 않아 낡은 오디오가 이어지다가 드롭으로 점프하며, 모듈 스스로 "UNVERIFIED on a real call"이라 적었다 ([live_bridge.py:20-23](../openai-agent-app/src/openai_agent/realtime/live_bridge.py#L20-L23)). **Realtime 엔진(사용 시)**: 델타 즉시 전송·페이싱 없음, `speech_started`마다 `clear`(오탐 = 단어 중간 절단), `conversation.item.truncate` 미전송 ([bridge.py:899-918](../openai-agent-app/src/openai_agent/realtime/bridge.py#L899-L918); [bridge.py:933-953](../openai-agent-app/src/openai_agent/realtime/bridge.py#L933-L953)) — 커뮤니티에서 반복 보고된 "faster than real time"(1초 만에 10초 분량 전송 → 끼어들기 창 1초) 및 "audio_end_ms를 잘못된 시계로 계산" 문제의 정확한 형태다(reported) ([openai-agents-js #1173](https://github.com/openai/openai-agents-js/issues/1173); [OpenAI thread 1371637](https://community.openai.com/t/openai-realtime-how-to-correctly-truncate-a-live-streaming-conversation-on-speech-interruption-twilio-media-streams/1371637)). 낮은 순위: 인사말 보이스 이음새(`cfg.openai_voice`로 렌더, 세션은 사업자 보이스) ([greeting_audio.py:50](../openai-agent-app/src/openai_agent/realtime/greeting_audio.py#L50) vs [live_session.py:181](../openai-agent-app/src/openai_agent/realtime/live_session.py#L181)), Traefik/Docker 네트워크 경로(코드가 "OpenAI가 멈춤"과 "OpenAI→VPS TCP가 멈춤"을 구분 못 함) ([docker-compose.yml:17-27](../openai-agent-app/docker-compose.yml#L17-L27)), 포워딩 가드 1.0 s ([settings.py:214-235](../openai-agent-app/src/openai_agent/config/settings.py#L214-L235)). 코드상 원인이 **아닌** 것: 청크 크기(Twilio는 어떤 크기든 순서대로 버퍼), base64 처리(패스스루), 수동 `commit`(미전송), 루프 위 동기 HTTP(전부 async/thread)(inferred).

외부 사례가 우리 우선순위를 뒷받침한다. OpenClaw는 상대적 `setTimeout(20)` 페이서가 35.59 s 동안 **+3,368 ms(+9.48%) 드리프트**, 25 ms 초과 60회·40 ms 초과 12회로 "Twilio's jitter-buffer concealment"가 "clipping/warble"을 냈고, `performance.now()` 단조 데드라인으로 바꾸자 **+5 ms(+0.015%)**, 평균 20.003 ms가 됐다(reported, 측정치) ([openclaw #119070](https://github.com/openclaw/openclaw/issues/119070)). openai-agents-python은 20–60바이트 델타를 즉시 전송하던 것을 ≥400바이트로 배칭했지만 리포터가 여전히 지터를 들어 **머지되지 않은 채 닫혔다** — 배칭만으로는 부족하다는 반증이다(reported) ([openai-agents-python PR #1926](https://github.com/openai/openai-agents-python/pull/1926)). Twilio는 `mark`를 "When that media message's playback is complete" 시점에 되돌려 주므로 재생 진실의 유일한 근거이고, `clear`는 "empties all buffered audio"다(documented) ([Twilio WebSocket messages](https://www.twilio.com/docs/voice/media-streams/websocket-messages)). LiveKit은 Twilio↔에이전트 전송만으로 **약 162 ms 편도**를 실측했고(reported) ([LiveKit thread 270](https://community.livekit.io/t/subject-325ms-one-way-audio-latency-in-sip-inbound-trunk-need-internal-pipeline-diagnostics/270)), Twilio Voice Insights는 캐리어 구간의 지터(경고선 30 ms)·손실·MOS를 10 s마다 주지만 Media Streams WebSocket 구간은 계측하지 않는다(documented) ([Voice Insights](https://www.twilio.com/docs/voice/voice-insights/advanced-features)) — "MOS는 멀쩡한데 끊긴다"면 WSS 구간 또는 브리지다(inferred).

## Conclusion

이 벤치마크의 가장 큰 반전은 "Bland는 자체 스택이라 끊기지 않는다"가 사실이 아니라는 점이다. Bland는 경쟁사 말대로 Twilio/SIP 파트너 위에서 돌고, 2026-09-25에는 자기 TTS가 "missing agent audio"를 냈으며, 외부가 본 지연은 우리와 같은 700–900 ms 대역이다. Bland가 실제로 다른 것은 **재생 버퍼를 사이에 둔 합성-전송 분리, 인정과 끼어들기를 구분하는 바지인, 리전 정렬, 그리고 통화가 끝난 뒤의 데이터 계약**이고, 이 네 가지는 모두 우리가 Twilio Media Streams와 GPT-Live 위에서 재현할 수 있다. 특히 우리 코드는 원인을 이미 주석에 적어 두었고 계측까지 붙여 두었으므로, 남은 일은 그 계측을 실제 끊긴 통화에서 읽고 `_caller_started_talking`의 드롭 조건 하나를 바꾸는 데서 시작한다.

제품 관점의 함의는 "따라잡기"가 아니라 "빈 층 채우기"다. Bland의 셀프서브는 업종 템플릿도, 영업시간 라우팅도, Google Calendar도, 한국어 실전도, 보이스메일함 전사도 주지 않는다 — 우리는 이미 갖고 있다. 반대로 통화 후 층(서명 웹훅·메모리·알림·요약 사용자화)과 배포 규율(diff·이력·게이트)은 비어 있고, 그것이 고객이 "받은 전화로 무엇을 할 수 있는가"를 결정한다. 끊김 수정과 "턴별 why" 통화 상세를 같은 데이터(브리지 텔레메트리)로 묶어 만들면, 엔지니어링 부채 상환과 제품 차별화가 한 작업이 된다.
