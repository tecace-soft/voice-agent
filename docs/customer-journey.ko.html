고객 여정: 데모에서 실제 전화 응대까지

이 제품이 무엇인지, 구성 요소가 어떻게 연결되는지, 어떤 기능이 있는지, 그리고 업체가 첫 데모부터 실제 전화를 받는 어시스턴트까지 어떻게 가는지 정리했습니다. 프로젝트를 처음 보는 사람도 따라올 수 있게 썼습니다.

1분 요약 9월 28일 이후 바뀐 것 시스템 구조 전체 기능 고객 여정 두 개의 게이트 실제 통화 어디서 되는지 남은 일 용어집

1분 요약

Voice Agent는 소규모 업체를 위한 AI 전화 응대원입니다. 손님이 업체에 전화했는데 아무도 받지 않으면(업체가 원하면 모든 전화를) 우리 어시스턴트가 받습니다. 자연스러운 목소리로 말하고, 업체 정보를 알고 있으며, 사장님이 설정한 대로 통화를 처리합니다.

  • 질문에 답변영업시간, 가격, 서비스, 위치, FAQ를 업체 프로필에서 찾아 답합니다.
  • 예약 잡기빈 시간을 확인하고 업체 캘린더에 직접 예약을 넣습니다.
  • 담당자 연결사람이 필요한 전화는 맞는 담당자에게 돌려줍니다.
  • 메시지 받기이름, 회신 번호, 용건을 대시보드와 Google Sheet에 남깁니다.
  • 링크 문자 보내기예약 페이지나 메뉴를 문자로 보냅니다. 데모에서만 되고 실제 전화는 아직입니다.

업체 (고객)

전화번호의 주인입니다. 데모를 써 보고 데모가 어떻게 쓰이는지 확인하고, 대시보드에서 어시스턴트를 설정해 퍼블리시하고, 자기 번호를 우리 번호로 포워딩합니다. 이후 통화와 메시지를 확인합니다.

TecAce 어드민

업체를 찾아 데모를 만들고, 셋업을 승인하고, 전화번호를 배정하거나 구매하고, 회선을 켭니다(Go live). 사용량을 지켜봅니다.

발신자

업체의 손님들입니다. 우리 제품을 볼 일은 없고, 평소처럼 업체에 전화해서 어시스턴트와 대화합니다.

9월 28일 이후 바뀐 것

어제 페이지는 0.0.9 버전 기준이었습니다. Main-Hans 브랜치는 이제 0.0.10입니다. Hans의 Twilio 번호 작업과 bottomup32의 커밋 네 개가 들어갔습니다. 이 섹션은 달라진 부분을 그림으로 보여 줍니다. 아래 전체 구조도에서도 같은 변경에 보라색 표시를 달았습니다.

화면 뒤에서

백엔드, 모델, 그리고 코드 변경 없는 발견 두 가지.

백엔드가 Twilio와 직접 통신신규transcribe-backend/src/twilio/의 얇은 fetch 클라이언트이며 SDK는 쓰지 않습니다. 자격 증명이 없으면 Twilio 라우트만 409 twilio_not_configured로 답하고 나머지는 그대로 동작합니다.
분석은 더 저렴한 모델로변경통화 후 리뷰와 리서치의 기본 모델이 gpt-5.6-luna가 됐습니다. 실제 통화의 도구 처리 모델은 gpt-5.6-terra 그대로입니다.
실제 통화의 전화 연결발견실제 전화는 고정된 연결 한 가지만 합니다. 설정의 시나리오는 아직 전화에 닿지 않습니다. 아래 표를 보세요.
프롬프트 편집기와 실제 통화발견전화 에이전트는 /business/config로 자체 프롬프트를 만듭니다. 저장된 프롬프트도 조합된 세션도 쓰지 않습니다.

Twilio 번호, phase 1

지금까지는 어드민이 번호를 직접 입력하고 웹훅은 Twilio 콘솔에서 설정했습니다. 이제 백엔드가 Twilio 자격 증명을 갖고 두 가지를 모두 처리합니다. 보라색 경로가 새로 생긴 것입니다.

  1. Phase 1 · 완료번호동기화, 검색과 구매, 웹훅, 반납, Go live에서 배정, 새 준비 상태 항목.

  3. Phase 3 · 이후문자 메시지toll-free 번호부터 시작합니다. 고객마다 10DLC 브랜드와 캠페인을 등록하는 대신 번호당 인증 양식 하나로 끝납니다.

데모 고객이 보는 화면

데모 단계 업체에는 읽기 전용 설정 화면 하나만 있었습니다. 이제 Overview, Call activity, Settings가 있는 자체 메뉴가 생겼습니다. 우리가 한 테스트 통화는 고객 숫자에서 빠집니다.

저장하면 프롬프트도 따라감

업체 설정과 데모 설정이 함께 쓰는 부분의 수정입니다. 이전에는 한 섹션에서 저장한 내용이 다른 섹션 때문에 되돌려질 수 있었습니다.

전화 연결: 설정이 약속하는 것과 실제 전화가 하는 것

9월 28일 점검 결과이며 코드 변경은 없습니다. Calls 설정의 전화 연결 시나리오는 앱 테스트 통화와 데모 통화에만 적용됩니다. 설정 화면과 시뮬레이터는 “press 1”을 안내하지만 실제 전화는 그렇게 동작하지 않습니다.

Phase 3 계획: 조합된 세션을 전화 에이전트에 제공하고, 컨퍼런스 기반 웜 트랜스퍼(대기 음악, 귓속말, “press 1”, 순차 연결)를 만들고, 운영 계정용 실제 연결 테스트를 추가합니다.

통화 중 도구 처리동일gpt-5.6-terra, OPENAI_BACKEND_MODEL로 지정.
통화 후 리뷰이전: terragpt-5.6-luna, CALL_REVIEW_MODEL로 지정.

환경 변수 값이 있으면 그 값이 우선합니다. 스테이징과 운영은 둘 다 설정하지 않아서 다음 배포 때 바뀝니다.

개발자용

  • transcribe-backend 새 환경 변수: TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, AGENT_PUBLIC_URL, TWILIO_VALIDATE_SIGNATURE, FORWARDING_TEST_TIMEOUT_SECONDS, TWILIO_MESSAGING_SERVICE_SID. Twilio 기능에는 PUBLIC_BACKEND_URL도 필요합니다.
  • agent_numbers에 Twilio 컬럼이 추가됩니다. 스키마는 스스로 마이그레이션합니다.
  • 새 뷰 #/my/overview, #/my/calls, #/billing. 새 공용 파일 src/settings/sections/LaunchGuide.tsx.
  • 회귀 테스트 셀렉터: 통화별 버튼은 “Open call details”, 시트 제목은 “Call details”. 새 스크립트 numbers_twilio.py.
  • 하네스 빌드가 이제 BACKEND_URL도 설정하므로, 로컬 .env 때문에 실제 백엔드로 연결되는 일이 없습니다.
  • 배포: 스테이징부터 Twilio 환경 변수를 설정하고, Sync from Twilio를 한 번 누른 뒤, 직접 등록했던 운영 번호를 Configure합니다.

Go live 체크리스트

  • 업체 정보가 채워짐
  • 통화 설정 퍼블리시됨
  • 전화번호 배정됨
  • 퍼블리시된 설정이 그 번호에서 동작
  • 번호로 온 전화가 에이전트에 도달 신규 (우리 Twilio 계정의 번호면 필수, 직접 등록한 번호면 안내만)
  • 업체에 연락할 번호가 등록됨 (경고만, 필수 아님)

어드민이 하는 일 (순서대로)

  1. 업체 추가(리서치는 선택)하고 CRM 단계 관리
  2. /c/<id> 데모 링크 보내기
  3. 셋업 요청 승인 또는 거절
  4. Go live 체크리스트 안에서 풀의 번호를 배정하거나 새로 구매
  5. 체크리스트 확인 후 Go live 클릭
  6. 통화 시간 확인, 피드백 답변

실제 통화에서 일어나는 일

업체가 번호를 포워딩하면 모든 전화가 전화 에이전트를 거칩니다. 에이전트는 전화를 받을 때 퍼블리시된 설정을 읽고, 통화 중에 도구를 호출하고, 끊으면 통화를 기록합니다.

기능별로 어디서 되는지

같은 설정이 세 종류의 통화에 쓰입니다. 새 기능은 앱 테스트 통화와 공개 데모에 먼저 들어가고, 실제 전화는 phase 3에서 따라잡습니다.

남은 일

자세한 내용과 테스트 체크리스트는 레포 루트의 TODO.md에 있습니다.

  • 개발포워딩 테스트와 통화 상태 신규Twilio phase 2. 지금은 업체가 실제로 포워딩을 걸었는지 확인하는 기능이 없습니다. 전화 에이전트 수정 세 건은 VPS가 실행하는 브랜치에 들어가야 합니다.
  • 개발실제 전화에서 링크 문자Twilio phase 3. toll-free 번호부터 시작합니다. 번호당 인증 양식 하나, 통화 중 동의 받기, STOP/HELP 처리가 필요합니다. 지역 번호용 10DLC는 뒤로 미뤘습니다.
  • 테스트실제 통화로 전화 연결받았을 때, 안 받았을 때(에이전트로 복귀), 제안만 했을 때와 약속했을 때, 연결 번호가 없을 때. 직원에게 어떤 발신 번호가 보이는지도 기록합니다.
  • 테스트실제 통화로 메시지 받기대시보드와 Google Sheet 기록, 회신 번호, 연결 실패 뒤 메시지. 업체에 가는 푸시 알림은 아직 없습니다.
  • Phase 3실제 전화에 조합된 설정 적용실제 통화는 아직 Python 룰북을 씁니다. 조합된 세션을 전화 에이전트에 제공한 뒤 컨퍼런스 기반 웜 트랜스퍼를 만듭니다. 영업시간 규칙과 메시지 브리프도 그때 함께 들어갑니다.
  • 스펙모든 통화에 같은 프롬프트 신규데모의 프롬프트 편집기는 데모 빌더의 내용(FAQ 5개, 각 140자 이내)을 보여 주고, 데모 통화는 세션 빌더를 쓰고, 실제 전화는 자체 프롬프트를 만듭니다. 스펙이 필요합니다.
  • 이후앱 안의 결제 신규Billing 페이지는 자리만 잡아 둔 상태입니다. 결제 기능이 생기면 이 페이지에 들어갑니다.
  • 배포스테이징, 그다음 운영에 Twilio 적용 신규Twilio 환경 변수를 설정하고, Sync from Twilio를 한 번 누르고, 직접 등록했던 운영 번호를 Configure합니다. Status callback만 추가되고 Voice URL은 VPS 그대로입니다.

데모 고객 (Demo customer)

단계 (Phase)
데모 → 온보딩 → 라이브. users.status에 demo, pre-production, production으로 저장.
초안과 퍼블리시 (Draft / Published)
설정 수정은 초안입니다. 테스트 통화는 초안을, 실제 전화는 퍼블리시된 것만 씁니다.
통화 설정 (Call settings)
메시지, 전화 연결, 링크, 예약 규칙. 설정 스튜디오의 Calls 그룹입니다.
조합된 세션 (Composed session)
설정으로 한 통화용 프롬프트와 도구를 만든 것. 지금은 앱과 데모 통화에서 씁니다.
룰북 (Rule book)
전화 에이전트의 자체 Python 프롬프트. phase 3에서 조합된 세션으로 바꾸기 전까지 실제 통화가 씁니다.
에이전트 번호 (Agent number)
업체에 배정된 Twilio 번호. 발신자가 직접 거는 번호는 아닙니다.
관리 번호 (Managed number)
우리 Twilio 계정에 있는 번호. 백엔드가 웹훅을 확인하고 고칠 수 있습니다. 직접 등록한 번호는 관리 번호가 아닙니다.
웹훅 (Webhooks)
Twilio가 번호마다 호출하는 URL: voice, fallback, status. 걸려 온 전화가 어디로 갈지를 정합니다.
착신 전환 (Call forwarding)
업체가 자기 번호를 에이전트 번호로 돌려 둡니다. 부재중만 또는 모든 전화.
리서치 (Research)
OpenAI 웹 검색으로 데모의 프로필, FAQ, 영업시간, 프롬프트를 채우는 작업.
통화 후 리뷰 (Post-call review)
데모나 테스트 통화가 끝나면 모델이 대화록을 읽고 요약, 발신자 기분, 어시스턴트가 답하지 못한 질문을 정리합니다.
고정된 프롬프트 (Frozen prompts)
직접 수정한 프롬프트. Rebuild하기 전까지 프로필과 FAQ 변경을 따라가지 않습니다.
